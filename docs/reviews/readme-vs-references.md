# Our README against three reference projects

Issue #117, 22 November 2026. Compared: Botbench's `README.md` before this change, and the READMEs, docs landing pages and site copy of OpenMausBot (`README.md`, `apps/docs/content/docs/index.mdx`), Paperclip (`README.md`, `docs/start/what-is-paperclip.md`, `doc/README-draft.md`) and Rakazo (`README.md`, `apps/www/src/i18n/home.ts`, `apps/www/src/subscription-faq.ts`). OpenMausBot's `enterprise/` folder was not read. Nothing below is copied into our README; the quotes are here to show the technique.

## What we take, in order of value

1. **A short, concrete opening, then the detail** (Rakazo's site lead, OpenMausBot's three lines). Our first paragraph becomes four short sentences about what happens, then one line on who it is for and what it is not. The conditions move to the sections that need them.
2. **Put the teamwork in the first screen, stated exactly** (Paperclip leads with the coordination problem it solves). Named workbenches and the view of other workbenches' pull requests are real today; the README now says so near the top, and says what is not built yet.
3. **Objections as questions** (Paperclip's FAQ, Rakazo's subscription answer). "Is it a sandbox?", "Does my code leave my Mac?", "May I use my subscription this way?", "Why not use Claude Code directly?", "Is anyone using it?" each get a short answer and a link.
4. **Proof a reader can check** (Paperclip's link to its merged pull requests). We link a pull request Botbench itself opened on this repository, with its evidence in the description, instead of a count.
5. **A before-and-after table of the job** (Paperclip's "Problems Paperclip solves"), kept to rows that are true of Botbench today.
6. **A moving demo near the top** (Paperclip's video). Marked as a place to record one; nothing is invented.
7. **"Choose your path" routing at the end** (OpenMausBot and Paperclip docs landing pages). Our "Where to go next" table already did this; it is kept and phrased as tasks.
8. **A clearly separate "what's next"** (Paperclip's roadmap, OpenMausBot's "Docs track released behavior"), with issue links instead of ticks.

## What we deliberately do not take

- **"Alternative to X" positioning and comparison tables against named products** (all three). Our positioning says the category is crowded and we never claim to be first; claims about other products would be unchecked here.
- **Badge rows, sponsor logos, star history, download buttons before the explanation.** The owner's standard lists "badges and a logo before any explanation" as a failure, and we have no release to download.
- **Emoji headings and feature grids** (OpenMausBot, Paperclip). They make every feature look equal and planned work look shipped.
- **Ticked roadmaps that mix shipped and planned** (Paperclip). Planned work stays in its own marked section.
- **Marketing adjectives** ("high taste", "handles the hard orchestration details correctly", "teammates you actually own"). Our rule is plain words and nothing that cannot be checked.
- **Testimonials and usage numbers.** We have none that are real and public.
- **"Ask your agent to install it"** (Paperclip, Rakazo). Not tested for Botbench; it may come later.

## Found while comparing

The quickstart's last step used the branch `botbench/run-1/task-1`. Since named workbenches (PR #87), new branches are `botbench/<workbench>/run-1/task-1`, with the workbench named after the Mac at first start (`src/workbench.ts`). The rewrite fixes the step; the screenshot `docs/images/ready-for-review.png` still shows the old name and is marked for a new capture.
